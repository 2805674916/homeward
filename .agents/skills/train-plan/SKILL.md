# 归途 / train-plan

用本目录 `scripts/search.py` 进行受限、串行的 12306 查询与候选段图搜索。不要代用户下单，不要将候补或车上补票描述为可立即购买的全程票。

## 输入与默认值

- 出发/到达城市、日期、到达截止为必要信息；人数默认 1、最早出发 00:00、最多换乘 3 次。
- 人数会参与余票容量判定：所有票段按"可买张数合计 ≥ 人数"核验（不同席别可拆单）。
- 到达截止不明确时可以从语义合理推断，例如“次日上午”取 12:00，并明确说明；只有改变实际搜索边界的歧义才向用户确认。
- 单人预算可选。官方查询节流至少 3 秒，不并发、不多开；`--max-queries` 默认 260（含约 50 次核价预留），低于 180 会明显削弱中转搜索，上限 400。全程约 15 分钟。

## 搜索覆盖

- 正常票直达与 1–3 次中转（同站 15 分钟、同城簇跨站 40 分钟；同车分段 2 分钟且不计换乘次数）。
- 直达拆票：售罄直达车按停站序列枚举购票区间（买短乘长/买长乘短/买长又买短/前站保上车站），有界尝试。
- 中转链救援：首末段售罄的一程中转按拆票区间重建。
- 输出经 Pareto 过滤（票价/历时/换乘/补票），未核价方案不参与支配比较。

## 运行

从本 skill 的 `scripts/` 目录运行（不要依赖当前工作目录）：

```bash
python search.py --from-city 上海 --to-city 武汉 --date YYYY-MM-DD \
  --after 18:00 --arrive-by "YYYY-MM-DD 12:00" \
  --people 2 --budget 800 --max-transfers 3 --max-queries 260 --out report.html
```

首次运行会把 12306 站名表下载到 `scripts/.cache/`；已打包的 Public Domain 省界位于 `assets/china_adm1.geojson`。`search.py --out` 一次生成包含 CSS、SVG、数据的离线 HTML。若只重绘已有 JSON，可运行 `python render.py plans.json report.html`。

向用户给出报告绝对路径及最值得关注的几个方案，明确每段的上车站、下车站、车次、换乘时间、实际可买席别和每人票价；拆票方案要说明票面区间与实际上车/补票区间的差别。仅当所有已购票段核价成功才报确定合计；带 * 的合计含补票参考价（按 12306 同车公布票价，补票段无座）；无座票价按同席别公布票价回退（动车组二等座/普速硬座）；接口缺价才标“待核价”。结果受候选枢纽、接口状态和查询额度限制，不是全国穷举；车上补票可能失败、无座。

说明地图是站点间地理示意，并非真实铁轨；余票、票价和时刻以 12306 官方页面为准。领域策略与风险见 `references/tactics.md`，搜索的候选段模型与完备性边界见 `references/math.md`。不公开用户真实行程报告、Cookie 或查询缓存。
